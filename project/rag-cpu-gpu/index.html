RAG pipeline on CPU and GPU

Measures where a retrieval-augmented generation (RAG) pipeline spends its time, then speeds up the slow parts with OpenMP on the CPU and CUDA on the GPU to see where parallelism actually pays off.

Overview

A RAG system answers a question in stages: it turns the question into a vector, searches a store of documents for the closest passages, and hands them to a language model to write the answer. Each stage is a different kind of work, so each gains differently from parallel hardware.

Instead of assuming the GPU wins everywhere, the project measures each component first and accelerates only where the numbers point.

Method

  1. Profile end to end

    Time every component of the pipeline to find where the time actually goes.

  2. Parallelise on the CPU

    Rewrite the heavy components with OpenMP across cores.

  3. Move to the GPU

    Port the same components to CUDA and run them on the graphics card.

  4. Compare honestly

    Measure the speed-up of each version against the original, component by component.
