Evolving KV-cache eviction

While a language model generates text it keeps a cache of past keys and values, and that cache grows with every token. This project uses a genetic algorithm to search for eviction policies that decide what to drop, and shows the trade-off between memory saved and output quality as a Pareto front.

Overview

Long conversations and long documents make the KV cache the main memory cost of serving a language model. Dropping entries saves memory but can hurt the answers, and the right balance depends on how much quality one is willing to give up.

So the search does not look for one best policy. It keeps every policy that is not beaten on both memory and quality at once, which is the Pareto front.

Method

  1. A policy as a genome

    Each candidate eviction policy is written as a genome the algorithm can cross and mutate. [How a policy is encoded.]

  2. Two scores

    Every policy is scored on the memory it saves and on the quality of the text the model produces with it.

  3. Evolve the front

    Selection, crossover and mutation over many generations keep the policies that no other policy beats on both scores.

  4. Read the trade-off

    The final front shows how much quality each step of memory saving costs.
